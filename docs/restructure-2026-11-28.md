## 4. 온라인 상품 마진 연결 단계 (E)

```
E01 온라인쇼핑몰 마진 ┐
                     ├ 마진 1/5 → E04 최대광고비 (광고 2/5) → E05 최저 목표 광고수익률 (광고 3/5)
E02 로켓배송 마진     ┘             → E06 셀러관점 광고수익률 (광고 4/5) → E03 상품 손익 (손익 5/5) → B07
```

- **건너뛰기**: 광고를 안 하는 사장님을 위해 E01·E02에 `Eltin.setFlow({ shortcut: "E03" })` → "상품 손익으로 바로 가기" 버튼 (B 분류에서 쓰는 기존 기능)
- **값 넘기기**: E01·E02가 지금 E03에 넘기는 값(`type, price, base, ebt, buy, fee, pack, ad, etc, vat` — M05-M06-E03.md)에 **입력값 그대로**(마켓·판매가·매입가·수수료율·포장비·광고비율·기타비율·개인/법인 등 MarginUI 입력 칸 값)를 더해 넘김
  - E04·E05: 받은 입력값으로 MarginUI 입력 칸을 채워 바로 결과를 보여주고, 다음 단계에는 **현재 입력 기준으로 다시 계산한** 같은 형식의 값(E01·E02가 넘기는 것과 동일)을 넘김. E04·E05에서 광고비율을 고치면 E03까지 반영됨
  - E06: 마켓 수수료율을 받아 채우고(광고수익률은 사용자가 마켓 화면을 보고 입력), 받은 값을 **그대로** E03에 넘김
  - E03: 지금처럼 받음. 아무 값 없이 열어도 지금처럼 동작
  - **주소 파라미터 이름 (코드 탭 11-28 확정, `assets/margin-ui.js`의 `flowQuery`·`received`·`passThrough`)**

    | 이름 | 뜻 | 단위 | 비고 |
    |---|---|---|---|
    | `type` | `direct`(온라인 쇼핑몰) / `rocket`(로켓배송) | | 기존 E03 값. 받는 쪽 판매 방식 칸도 이것으로 고름 |
    | `price` | 판매가 (로켓은 쿠팡 판매가) | 원 | 기존 E03 값 = 입력 칸 값 |
    | `base` | 기준 금액 (온라인 = 판매가, 로켓 = 납품가) | 원 | 기존 E03 값 |
    | `ebt` | 1개 세전 이익 (음수 가능) | 원 | 기존 E03 값 |
    | `buy` | 매입가·제조원가 | 원 | 기존 E03 값 = 입력 칸 값 |
    | `fee` | 마켓수수료 금액 (로켓은 0 — 납품가에 이미 빠짐) | 원 | 기존 E03 값 |
    | `pack` | 포장비 | 원 | 기존 E03 값 = 입력 칸 값 |
    | `ad` · `etc` · `vat` | 광고비 · 기타비용 · 부가세 금액 | 원 | 기존 E03 값 |
    | `market` | 판매처 선택 번호 (판매 방식별 목록의 순서, 0부터) | | **신규** |
    | `feer` | 마켓수수료율 | % | **신규** · E06도 이 값으로 수수료율 칸을 채움 |
    | `adr` · `etcr` · `taxr` | 광고비율 · 기타비용 비율 · 소득세율 | % | **신규** |

    - 받는 쪽은 신규 값(`market`·`feer`·`adr`·`etcr`·`taxr`) 중 하나라도 있으면 입력 칸을 채움 (E04 바로, E05는 "마진 정보" 방식으로 열어서). 없으면 지금처럼 기본값
    - E05를 "간단 계산"으로 바꾸면 받은 값을 그대로 넘김. E06은 항상 받은 값을 그대로 넘김 (`member`·`open`·`embed`는 공통 JS가 다시 붙여서 뺌)
- 결과 문구에 "다음 단계" 버튼은 공통 JS가 붙이므로 계산기마다 따로 넣지 않음 (기존 규칙)
