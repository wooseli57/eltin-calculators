# 색·향 계산기 연결 사양 (R01·R02·R04·G02·G03·G04·G05)

상태: 연결 구조 확정 (2026-11-24 채팅). 각 계산기의 수치 데이터는 엘틴 자료를 받은 뒤 채움.
R01·R02·G 계산기를 만들 때와 R04의 연결 버튼을 만들 때 이 문서를 함께 따릅니다.

## 1. 역할 나누기

| 계산기 | 답하는 질문 | 받는 값 | 넘기는 곳 |
|---|---|---|---|
| R04 엘틴 레시피 | 무엇을 얼마나 만들까 (색소 없는 표준 레시피, 바닐라 포함) | - | R01(바탕·무게), R02(무게) |
| R01 색소 사용량 | 이 양에 이 색을 내려면 색소가 얼마나 (g·방울·비용) | 바탕, 무게, 색(단일 제품 또는 G05 배합), 농도 | G03 |
| R02 향료 사용량 | 이 양에 향료가 얼마나 | 무게, 향료 | - |
| G05 인기 색 레시피 | 인기 색은 어떻게 섞나 (배합표) | 바탕(선택) | R01 |
| G02 색 배합 | 원하는 색을 내려면 어떤 조합으로 | 목표 색, 바탕 | R01 |
| G03 농도 조절 | 이미 만든 색을 진하게·연하게 하려면 | 현재 배합·무게, 목표 농도 | - |
| G04 색소 단위 변환 | 방울 ↔ g, 액상 ↔ 분말 | 제품, 양 | - |

```
 G05 인기 색 배합표 ─┐
 G02 원하는 색 → 배합 ┼─(어떤 색)──▶  R01 색소 사용량 ◀──(무엇에·몇 g)── R04 엘틴 레시피
                    │              (g·방울·비용)                       │
 G03 색 진하게·연하게 ┘                                                └─(몇 g)──▶ R02 향료 사용량
```

- R01이 중심입니다. 색소 양 계산은 R01에서만 하고, 다른 계산기는 R01로 값을 넘기거나 R01과 같은 함수를 씁니다.
- R04는 색소·향료(바닐라 제외) 양을 직접 계산하지 않습니다.

## 2. 공통 데이터 파일 (한 곳에서만 관리)

엘틴 자료를 한 번 넣으면 모든 계산기에 같이 반영되도록 데이터는 아래 파일에만 둡니다. 계산기 파일 안에 수치를 따로 적지 않습니다.

| 파일 | 내용 | 쓰는 계산기 |
|---|---|---|
| `data/eltin-colors.json` | 색소 제품: id, 이름, 색, 형태(액상·젤·분말), 1방울 무게(g), 용량, 가격, 쓸 수 있는 바탕(`bases`), 권장 사용량(바탕 100g당 g, 농도 단계별), 쇼핑몰 링크 | R01, G02, G03, G04, G05 |
| `data/color-bases.json` | 바탕 종류: id, 이름, 바탕색 안내(예: 버터크림은 노란빛이라 파랑이 초록빛으로), 보정 배율(기본 1), 주의 문구 | R01, R04, G02, G03, G05 |
| `data/color-recipes.json` | 인기 색 배합: id, 색 이름, 바탕, 표시 색 코드, 색소 조합(제품 id와 바탕 100g당 g) | G05, G02, R01 |
| `data/eltin-flavors.json` | 향료 제품(id, 이름, 형태, 가격, 링크)과 사용 기준. **바닐라 사용 기준(밀가루 125g·우유 250ml당 5ml, 버터 225g당 15ml)도 여기 둠** | R02, R04 |

- 바탕 종류 id: `whipped-cream`(생크림), `buttercream`(버터크림), `meringue`(머랭), `batter`(반죽), `icing`(아이싱), `rice`(쌀가루), `drink`(음료), `jelly`(젤리), `sugar`(설탕), `chocolate`(초콜릿)
- 색 배합과 권장 사용량은 모두 **바탕 100g당**으로 적습니다. 양이 바뀌면 비례 계산만 합니다.
- 초콜릿처럼 물이 들어가면 안 되는 바탕은 `eltin-colors.json`의 `bases`에 없는 제품을 R01·G02에서 고를 수 없게 합니다.
- 데이터가 아직 없으면 파일은 빈 목록으로 두고, 화면에는 "엘틴 데이터 준비 중이에요"를 표시합니다.

## 3. 계산기끼리 값 넘기기 (주소 형식)

| 받는 곳 | 주소 예 | 파라미터 |
|---|---|---|
| R01 | `r01-color-dosage.html?base=buttercream&g=500&color=pastel-pink&level=2` | `base` 바탕 id, `g` 무게(음료는 `ml`), `color` 제품 id 또는 G05 배합 id, `level` 농도 단계(1 연하게·2 보통·3 진하게), `from` 보낸 계산기(예: `r04:2`) |
| R02 | `r02-flavor-dosage.html?g=410&flavor=lemon` | `g` 또는 `ml`, `flavor` 향료 id, `from` |
| G05 | `g05-color-recipes.html?base=whipped-cream&c=pastel-pink` | `base`, `c` 배합 id |

- 모든 파라미터는 선택이며, 없거나 잘못되면 기본값으로 엽니다 (오류 없이).
- 블로그 글에서도 같은 주소로 계산기를 바로 열 수 있습니다.
- `from`이 있으면 R01·R02 결과 아래에 "← 레시피로 돌아가기" 링크를 둡니다.
- 받은 계산기가 아직 없으면(상태가 완료 아님) 보내는 쪽 버튼은 회색 "준비 중"으로 표시합니다. 공통 JS에 `Eltin.ready(['R01'])` 같은 확인 목록을 두고 계산기가 완성될 때 갱신합니다.

## 4. 계산기별 연결 동작

### R04 → R01·R02
- 레시피 문서의 `색을 넣으려면` 줄(단계·바탕·색 입힐 양)을 데이터로 변환: `color: { step, base, grams }`.
- `향을 바꾸려면` 줄: `flavor: { step, label, grams }`.
- 재료 표 아래에 안내와 버튼: "원하는 색을 내려면 ○단계에서 ○○에 넣어요. **[이 양에 색 입히기]**" → R01로 `base`, `g`(현재 분량 기준으로 다시 계산한 값), `from=r04:<id>` 전달.
- 레시피에 색 넣는 곳이 없으면 버튼을 보여주지 않습니다.

### G05 → R01
- 색 카드마다 "바탕 100g당 배합"을 보여주고, **[내 양으로 계산]** → R01로 `color=<배합 id>`, `base`.
- 색 놀이 레시피(`docs/recipes/color-play.md`: 놀이 반죽, 컬러 슈가)는 G05 하단 "색 놀이" 묶음 또는 블로그 글로 사용.

### G02 → R01
- 목표 색을 고르면 먼저 `color-recipes.json`에서 가장 가까운 배합을 찾아 보여주고, G01 모델이 준비되면 계산한 조합도 추가.
- 결과의 **[이 배합으로 양 계산]** → R01.

### R01 → G03
- R01 결과 아래 "색이 생각보다 연하거나 진한가요? → 농도 조절" 링크 (현재 배합·무게 전달).

### R02 ↔ R04 바닐라
- R04의 바닐라 양과 R02의 바닐라 계산은 같은 `eltin-flavors.json` 기준을 씁니다. 기준이 바뀌면 둘 다 같이 바뀝니다.

## 5. 작업 순서

1. R04는 R01 수치 없이 지금 만들 수 있음 (연결 버튼은 "준비 중").
2. 공통 데이터 파일 4개는 빈 틀(형식)만 먼저 만들고, 엘틴 자료가 오면 채움.
3. R01 → G05 → G04 → R02 → G02·G03(G01 모델 필요) 순서로, 데이터가 확정되는 대로 사양을 씀.
