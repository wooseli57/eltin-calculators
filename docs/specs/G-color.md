# G. 조색 가이드 사양 (G01~G07)

> **2026-11-28 번호 변경: G04~G07 → K01~K04** (색소놀이 조색 가이드 K. 클레이 K01·K02, 물 K03·K04 — 물은 홈베이킹 조색 가이드 G 목록에도 보임). 이 문서의 G04~G07은 K01~K04로 읽기. `docs/restructure-2026-11-28.md`

상태: 사양 확정 (2026-11-27 채팅). `docs/specs/color-flavor-links.md`의 G 부분은 이 문서로 대체합니다(연결 구조·방울 기준은 그대로).

## 0. 바뀐 점과 결정

- 바탕을 3가지로: **생크림**(G01~G03), **클레이**(G04·G05), **물**(G06·G07 신규). 계산기 64개 → 66개.
- 계산 방식: K/S 모델 대신 **엘틴 측정표에서 찾기**.
  - 채팅에서 K/S(빛 흡수·산란) 모델을 이 데이터로 맞춰 봤더니 평균 색차가 생크림 ΔE 19, 물 ΔE 15, 클레이 ΔE 8로 눈에 띄게 틀림. 측정표는 방울 1개 차이가 ΔE 4 정도로 촘촘함.
  - 그래서 혼색 예측은 측정된 컬러칩을 그대로 보여주고, 색 배합은 측정된 칩 중 가장 가까운 것을 찾음. 측정 범위 밖 조합은 계산으로 지어내지 않고 "측정 범위 밖"으로 안내.
- 조색 가이드는 모두 **회원 전용**(`data-access="member"`).
- 물 계산기 용도: 물 색소놀이·음료·젤리 모두 해당 (대표 확인 2026-11-27).
- **화면 안내 문구는 색을 추출한 방법만** (1절 측정 조건을 쉬운 말로). 사용 팁·주의 문구는 넣지 않음 (대표 결정 2026-11-27). 물 데이터는 색소를 1/100로 묽혀 종이에 떨어뜨려 말린 색이라 **색의 비율(색감)**을 알려주는 계산기이고, 내 양에 넣을 방울 수는 계산하지 않음.

## 1. 원본 데이터와 측정 조건

원본 엑셀: `자료/컬러칩 데이터/` (내부 자료, 공개 저장소 제외)

| 바탕 | 파일·시트 | 측정 조건 (화면 "계산 기준"에 쉬운 말로 표시) | 칩 수 |
|---|---|---|---|
| 생크림 | `식용색소_조색데이터 (생크림).xlsx` — 단색 48색 매트릭스, B 2색조합, C 3색조합 | 생크림 10g에 엘틴푸드칼라를 떨어뜨려 완전히 섞은 뒤 가장 비슷한 색의 RGB 기록 (엘틴 컬러칩북) | 단색 48색 × 1·2·4·6·8·10방울 = 288, 2색 140, 3색 56 |
| 클레이 | `식용색소_조색데이터 (클레이_물).xlsx` — 클레이 2색, 클레이 3색 | 시판 흰색 클레이 **5g**에 방울 수만큼 섞은 색 (엘틴 자료실 148·149) | 2색 700 (각 1~5방울), 3색 1,512 (각 1~3방울) |
| 물 | 같은 파일 — 물 2색, 물 3색 | 진한1 색소를 **1/100로 묽혀** 정한 비율로 섞고, 0.015ml 한 방울을 Kodak 고광택 인화지에 떨어뜨려 말린 뒤 스캔(600dpi)해 RGB 추출 (엘틴 자료실 146·147) | 2색 2,268 (각 1~9), 3색 1,512 (각 1~3) |
| 공통 | 같은 파일 — 기본 8색 | 진한1 8색 대표 컬러코드 (자료실 145) | 8 |

- 색 이름·약자: 생크림 엑셀 "안내" 시트의 약자 범례 (YE 노랑, OR 주황, PI 분홍, RE 빨강, GR 초록, BL 파랑, VI 보라, BK 검정 … 계절 스페셜 포함 48색).
- 클레이·물은 진한1 8색(YE OR PI RE GR BL VI BK)만 있음.
- 엑셀 "비고"에 "이미지 속 물방울 색은 #… (표기 코드와 다름)"이 있는 칩은 ~~표기 코드를 쓰고 `note`에 남김~~ → **사진 속 색**을 쓰고 표기 코드는 `note`에 남김 (대표 결정 2026-11-27. 표기 코드가 다른 칩 코드를 잘못 옮겨 적은 경우가 확인됨). 바꾼 칩 목록은 `data/color-chips.json`의 `_corrections`

## 2. 데이터 파일: `data/color-chips.json`

`tools/build-color-chips.py`가 위 엑셀 2개에서 만듦 (직접 고치지 않음, `build-calculators.py`처럼 검사 포함). 엑셀이 없으면(공개 저장소) 기존 JSON을 그대로 두고 경고만.

```json
{
  "dropMl": 0.04, "density": 1.05,
  "colors": { "YE": { "name": "노랑", "group": "진한1", "hex": "#FBC80A" }, "LE": { "name": "레몬옐로우+", "group": "계절스페셜-봄", "hex": "#…" } },
  "bases": {
    "cream": { "name": "생크림", "amount": 10, "unit": "g", "levels": [1,2,4,6,8,10],
      "single": { "YE": ["#f8ff92","#fff766","#ffef1d","#ffe71b","#ffe102","#ffd803"] },
      "chips": [ ["B2","EL-C-YE1OR3","주황3","#ffa84a",{"YE":1,"OR":3}] ] },
    "clay":  { "name": "흰 클레이", "amount": 5, "unit": "g", "range2": 5, "range3": 3,
      "chips": [ [{"YE":1,"OR":2},"#FFB25B"] ] },
    "water": { "name": "물", "amount": null, "dilution": "1/100", "range2": 9, "range3": 3,
      "chips": [ [{"YE":1,"OR":2},"#DF7532"] ] }
  }
}
```

- 단색 대표색 `colors.*.hex`: 진한1 8색은 "기본 8색" 시트 값. 나머지 40색은 생크림 10방울 값.
- 검사: 칩 수(위 표), 방울 범위, HEX 형식, 같은 조합 중복 없음, 생크림 단색 48색 × 6단계.
- 파일 크기를 줄이려 배열 형식 사용 (예상 150~250KB). G 계산기에서만 불러옴.

## 3. 공통 기능 (`assets/eltin-color.js` 새 파일, G 계산기만 불러옴)

- `ColorData.load()` — color-chips.json 한 번 읽기
- `toLab(hex)`, `deltaE(hexA, hexB)` — **CIEDE2000**
- `lookup(base, mix)` — 측정된 칩 찾기. 없으면 `null`
- `creamSingle(color, drops)` — 생크림 단색: 1·2·4·6·8·10은 측정값, 3·5·7·9는 양옆 측정값을 Lab에서 반씩 섞은 **중간값**(표시: "측정 사이 중간값")
- `nearest(base, targetHex, opt)` — 그 바탕의 모든 칩(+생크림 단색 중간값) 중 ΔE가 작은 순서. `opt.colors`(가진 색만), `opt.maxColors`(1~3)
- 색차 말로 표시: ΔE ≤2 "거의 같아요" / ≤5 "비슷해요" / ≤10 "조금 달라요" / 그 이상 "가장 가까운 색이에요 (차이가 있어요)"
- 색 칩 그림: 큰 사각 견본(가로 결과 카드 폭, 높이 72px, 둥근 모서리) + HEX + 칩 번호/코드. 목표색과 비교할 때는 왼쪽 "원하는 색" / 오른쪽 "엘틴 배합" 두 칸
- 방울 → g: `방울 × dropMl × density` (소수 둘째 자리), 방울 수는 정수 반올림
- 계산 기준 칸: 그 바탕의 **색 추출 방법만** (1절 표의 측정 조건). 다른 안내 문구는 넣지 않음

인기 색 버튼 (G02·G05·G07 공통, `data/color-presets.json`): 파스텔 핑크 #F8C8DC, 코랄 #FF7F6E, 피치 #FFCBA4, 레몬 #FFF176, 민트 #A8E6CF, 하늘색 #A7D8F0, 라벤더 #C3B1E1, 네이비 #1F2A5A, 초콜릿 브라운 #6B3E26, 레드벨벳 #A4161A. (목표색일 뿐 엘틴 배합이 아님. 배합은 nearest로 찾음)

## 4. 계산기별

### G01 생크림 혼색 예측 (`g01-color-mix.html`)
- 입력: 섞는 색 개수 [1색 | 2색 | 3색]
  - 1색: 색(48색, 그룹별 묶음 선택) + 생크림 10g당 방울 수 1~10
  - 2색: 기본 8색 중 2개 + 비율 [1:1 · 1:3 · 3:1 · 1:9 · 9:1] (측정된 것만)
  - 3색: 기본 8색 중 3개 (각 1방울)
  - 내 생크림 양 g (기본 300)
- 결과: lead "이 배합이면 이런 색이 나와요" + 색 견본 + 칩 이름·코드 / rows: 생크림 10g당 배합, 내 양에 넣을 방울·g(색별)
- 버튼: "이 색을 기준으로 배합 찾기 →" G02 (`?hex=`)

### G02 생크림 색 배합 (`g02-color-match.html`)
- 입력: 원하는 색 (색 고르기 `input type=color` + HEX 칸 + 인기 색 버튼), 가진 색소(기본 8색 체크, 기본 전부, 계절·진한2·3 포함 여부 토글), 내 생크림 양 g (기본 300)
- 결과: 가까운 배합 **3개** (각각: 비교 견본, 색차 말, 생크림 10g당 배합, 내 양 방울·g)
- 버튼: "이 배합으로 양 계산 →" R02 (R02가 준비 중이면 회색, 공통 규칙)
- 주소: `?hex=F8C8DC` 또는 `?c=pastel-pink`, `&g=300`

### G03 생크림 농도 조절 (`g03-color-strength.html`)
- 입력: 지금 넣은 색소 (1~3색, 색별 방울 수), 지금 생크림 양 g, 바꾸고 싶은 정도 [절반으로 연하게 · 조금 연하게(2/3) · 조금 진하게(1.5배) · 2배 진하게]
- 계산: 농도 = 방울 ÷ 생크림 g
  - 진하게(배율 f>1): 색별 추가 방울 = 지금 방울 × (f − 1)
  - 연하게(f<1): 추가 생크림 = 지금 생크림 × (1/f − 1)
- 결과: lead "노랑 2방울을 더 넣으세요" / "생크림 150g을 더 섞으세요"
- 미리보기: **1색**이고 생크림 10g당 환산 방울이 1~10 안이면 지금 색·바꾼 색 견본 2개 (creamSingle). 2~3색이면 "섞은 색은 측정 자료가 없어 미리보기 없이 양만 알려줘요"
- 범위 밖(10g당 10방울 초과): 미리보기 대신 "측정 범위(생크림 10g당 10방울)보다 진해요"

### G04 클레이 혼색 예측 (`g04-clay-mix.html`)
- 입력: [2색 | 3색], 기본 8색에서 고르기, 클레이 5g당 방울 (2색 1~5, 3색 1~3), 내 클레이 양 g (기본 50)
- 1색은 측정 자료가 없어 선택지에 없음 (G06도 같음)
- 결과: 견본 + 클레이 5g당 배합 + 내 양 방울·g. 버튼 → G05 (`?hex=`)

### G05 클레이 색 배합 (`g05-clay-match.html`)
- G02와 같은 구조. 칩은 클레이 2·3색, 가진 색소는 기본 8색, 내 클레이 양 g (기본 50)
- 결과 3개 + 내 양 방울·g

### G06 물 혼색 예측 (`g06-water-mix.html`) — 신규
- 입력: [2색 | 3색], 기본 8색에서 고르기, 섞는 비율(방울 수: 2색 1~9, 3색 1~3)
- 결과: 견본 + "노랑 2 : 파랑 1 비율로 섞은 색이에요". **내 양 계산 없음**
- 계산 기준: 물 색 추출 방법 (1/100 희석, 정한 비율로 섞어 0.015ml 한 방울을 고광택 인화지에 떨어뜨려 말린 뒤 스캔해 RGB 추출)
- 버튼 → G07 (`?hex=`)

### G07 물 색 배합 (`g07-water-match.html`) — 신규
- G02와 같은 구조, 칩은 물 2·3색. 결과는 **비율**로만 (예: "노랑 3 : 초록 1")
